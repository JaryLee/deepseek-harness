# @deepseek-ai/dsh-client-desktop-notify

[English](README.md) | 中文

## 概述

`dsh-client-desktop-notify` 在会话结束或向你提问时提醒你，并且挑你真正看得见的渠道：页面隐藏时发系统通知，页面可见时在应用内让鲸鱼跃出水面，开启提示音后还会播放合成的鲸鱼叫声。一个包里同时包含两半：宿主半侧注册 `desktop-notify` 设置分区，浏览器半侧读取该分区，并结合会话列表、转发的 Agent 状态和待处理交互流。通知是显式开启的——`enabled` 默认为 false，需要在「设置 → 插件」的卡片里打开。

<a id="use-this-package"></a>
## 使用本包

在「设置 → 插件 → 桌面通知」里打开开关，并在同一张卡片上授予浏览器通知权限。此后，会话结束、向你提问、请求授权或提交待审计划时都会提醒你。

### 两个渠道

页面按自身可见性决定渠道。窗口最小化或标签页在后台时只发系统通知，因为页面里的任何提示都看不见。页面可见时先在页面内显示鲸鱼提示；只有当你关掉「仅在页面隐藏时用系统通知」（默认开启）时，才会再补一条系统通知。提示音开关只作用于可见页面这一路；页面隐藏时声音交给操作系统。

### 阅读鲸鱼提示

提示会停留七秒，并且整条都可操作。点击气泡会把提示对应的会话切到前台，关闭按钮则提前收起这次提示。每次提示都有自己的身份标识，因此关闭一次不会误清掉后来替换上来的提示。

### 重试与静默窗口

在静默窗口内停了又开始的会话不会被通知：这个窗口用来区分「中途暂停的一轮」和「真正结束的会话」。如果会话结束时它的列表行还没到达页面，通知会随会话列表的变化重试，四次之后放弃。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现内部细节——点击展开</summary>

浏览器半侧负责浏览器相关的事：通知要报出哪个会话、页面当前能做什么，以及两处 slot 注册。通知规则本身藏在端口之后，因此不依赖 DOM 就能测试。

### 信号

一次「完成」来自两个必须一致的信息源：转发的 `api-session/status` 远程事件说明某个 Agent 停了，会话列表行则说明那是哪个会话。列表同时也是页面加载时判定「正在运行」的依据，因此刷新后才观察到的完成仍然能报出会话名。待处理的提问来自 `ctx.uiSession.pendingInteractions`，条目的不透明请求 key 就是引擎标记「已通知」的依据；条目上的判别字段（`question`、`plan-review`、`approval`）决定通知的措辞。

### 通知规则

引擎对每次完成或提问只发一条通知。每条提问最多通知一次，只有真正发出通知后才按请求 key 打标记，并在它离开待处理集合后遗忘标记。静默窗口、可见与隐藏两个渠道、重试上限都是端口，因此可以用测试驱动，不需要浏览器。

### 鲸鱼、音效与图标

提示是一张扁平插画用它自己的图层搭出来的。最底下是整幅场景；上面五条从同一片海裁出的浪带按各自的速度、方向与起伏来回滚动，每条都首尾各放一份，因此平移半个宽度就是无缝循环，另有一条光带横掠涌浪。鲸鱼按自己的曲线跃出——背脊贴在水面、整头出水、在最高点转身、再落回——水花每轮炸两次，用的是同一张素材的两个实例：一次随鲸鱼出水，一次随它落回，每次都会甩出自己的水珠。消息浮在场景上方那只自带的水泡里，三颗气泡从鲸鱼升向它；场景本身四边渐隐，而不是收在一条卡片边上。在 `prefers-reduced-motion` 下，鲸鱼保持贴水面的姿态，海面停止流动。

音效用 Web Audio 合成，因此包里不带任何音频资源：一声座头鲸的呼唤、破水的水花，以及两只海鸥。尚未收到用户手势的页面，其音频上下文处于挂起状态，此时排程的音源会在恢复时一起爆响；这种情况下直接跳过音效并打印一条控制台警告。通知图标是把品牌标记按图标尺寸栅格化得到的，画布 API 不可用时回退到站点 favicon。

</details>

<a id="model-experience"></a>
## 模型体验

无，因为本包是浏览器侧的通知插件，不注册任何会话事件，也不触及任何模型请求。

#### KV Cache effect

无；本包既不组装也不发送任何 provider 请求。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

以下是本功能当前的约束。

- **提示横幅由操作系统绘制** —— 若部署方的通知设置关闭了横幅，通知只会出现在操作中心里，页面侧代码无法改写这一点。
- **音效需要用户手势** —— 浏览器在用户与页面交互之前会一直挂起页面音频，因此刚打开的页面上第一次提示只有画面。
- **拒绝权限后要在应用外恢复** —— 卡片可以请求权限，但被拒绝的权限只能在浏览器的站点设置里重新允许。
- **列表行始终不来的完成会被丢弃** —— 连续四次列表更新仍没有该会话的行就停止重试，因为通知无法报出页面从未见过的会话。

**运行时不变式：** 不发布伴随包。通知通过各自的订阅读取归属方作用域内的状态——待处理交互流与会话列表——它们施加的每条规则都由本包的测试直接覆盖。
