# Agent Note（代理注记）：Web 费用计费器——峰谷费率与会话总量改为求和

状态：已实现（implemented）

[English](2026-09-10-web-cost-peak-off-peak-and-summed-session-total.md) | 中文

## 问题

已交付的 [Web token 与费用表](2026-08-27-web-token-and-cost-meter.zh.md) 对每个步骤都用同一个按模型的固定费率计价，并用全量日志的 `tokenUsage` 投影、按会话最新模型路由计算会话费用行。由此产生两个问题：一个中途切换模型的会话会给出近似总量，且可能与单回合徽标不一致；而提供方引入了分时计价——工作日高峰时段之外费率更低、周末全天按空闲——单一费率无法表达。

## 决策

### 峰谷费率

内置费率表现在存放公开的**峰值**费率。空闲计价在 `peakWindows` 内对每个桶施加 `offPeakFactor`（默认 `0.5`，即公开的半价）；`peakWindows` 默认取公开排期：工作日 UTC 01:00–04:00 与 06:00–10:00，周末全天按空闲。两者都是配置字段，遵循「插件中不写死可调项」规则，因为提供方的费率与排期是随部署变化的外部规范。模型也可以声明同名字段的显式 `offPeak` 费率，此时直接采用。

`isPeakTime` 由某一时刻的 UTC 星期与当日分钟判断是否高峰；`billedAt` 为某个 assistant 步骤选出要计价的时刻——有记录的步骤起始时间时用它，否则用完成时间；`ratesAt` 把费率条目与时刻化为实际适用的费率。以请求起始为准是因为提供方按请求计费，而窗口未记录步骤起始时，完成时间是唯一可退回的观测。

### 会话总量：已加载窗口的求和

`TotalCost` 不再读取 `tokenUsage` 投影。它把已加载对话窗口内的每个 assistant 步骤求和，各自按其模型以及运行时刻的峰谷费率计价，因此费用行按构造等于各单回合徽标之和。这反转了先前"持久投影"的取舍：费用行现在受窗口限制，被翻页或压缩移出窗口的回合不再贡献。持久投影本身仍然存在，仍支撑统计条；只是本插件不再读取它。

### 只对单步采样做一种归一化

投影计价移除后，`normalizeUsage` 只读取单步提供方 `TokenUsage` 采样（`inputTokens` 及缓存与输出字段），不再接受全量日志投影形态。

## 备选方案

- **保留持久投影并加 per-model/per-time 拆分** —— 准确且抗翻页，但需要 Host 侧投影改动（按模型、按时段的拆分）及其测试。推迟；窗口求和已覆盖所展示的两处界面，且不改动持久形状。
- **对全部模型施加单一全局折扣，而不是每模型各自的空闲费率** —— 否决。提供方排期是外部规范且可能因模型而异，显式的每模型 `offPeak` 保留这一空间，而倍率覆盖统一情形。
- **按完成时间划分峰谷** —— 否决。提供方按请求计费，而记录的步骤起始是更贴近的可观测项。

## 后果

两处界面现在都读取已加载窗口并按构造一致，因此"模型切换后两处界面不一致"的限制消失；接受的代价是会话费用行不再扛过分页与压缩。峰谷是提供方排期的客户端近似：它使用 UTC 工作日时段与步骤的可观测时刻，内置费率与时段需按部署核对——本插件仍不发起任何网络请求。`pricing`、`currency`、`peakWindows` 与 `offPeakFactor` 均可由 cordis.yml 配置：[客户端配置投递](2026-09-10-client-plugin-config-delivery.zh.md) 让每一行的 config 经由启动图抵达插件。费率表无法计价的模型仍不显示费用，但由于该表以路由记录的确切 id 为键，更名的 id 会让两处界面变空且没有任何信息指出原因；现在每个无法计价的 id 会按页面各上报一次 `console.warn`，指明需要补充的 `pricing` 键。没有改动 Session 格式、事件或投影形状，因此没有既有捕获输出移动；本插件自身测试覆盖排期、费率选择、两处推导以及两个渲染器。
